# مراقب رسائل واتساب أبو الفيصل — أربع دقائق فقط

## المتطلب النهائي

1. مراقبة المحادثات الفردية الواردة إلى **رقم واتساب أعمال الحالي**.
2. عند وصول رسالة بعد آخر رد للموظفين، يبدأ عداد **4 دقائق**.
3. إذا رد أي موظف من تطبيق WhatsApp Business أو جهاز متوافق ويصل ردّه عبر \`smb_message_echoes\`، يُلغى الانتظار.
4. إن مرت أربع دقائق دون رد مسجل، يُنشأ **تنبيه واحد فقط** لتلك فترة الانتظار؛ لا يكرر عند وصول عدة رسائل متتابعة.
5. لا يرد البوت على العميل. لا يفتح حجزًا، ولا يصنف تأشيرة، ولا ينزل صورًا أو مقاطع صوتية.
6. سجلات المراقبة تشمل اسم العميل ورقمه وأوقات وصول الرسائل والردود فقط، وليس نص المحادثة أو المرفقات.

## شكل الرسالة

🔔 تنبيه أبو الفيصل

العميل: [الاسم إن وجد]
الرقم: [رقم واتساب العميل]
لم يتلقَّ ردًا من الموظفين منذ 4 دقائق.
يرجى المتابعة.

**تنبيه مهم:** هذه الرسالة تُنشأ الآن في قائمة انتظار خاصة، ولا تُرسل تلقائيًا إلى أي جروب واتساب.

## لماذا لا تصل إلى جروب واتساب الحالي؟

التكامل الرسمي **Coexistence** بين تطبيق واتساب أعمال وWhatsApp Cloud API يدعم استقبال رسائل العملاء ورصد ردود الموظفين عبر \`smb_message_echoes\`، لكنه لا يمنح صلاحية نشر رسائل تلقائية إلى مجموعات واتساب الحالية. واجهة Groups API الرسمية **غير متاحة لأرقام Coexistence**؛ وكذلك المجموعات القائمة لا يمكن تحويلها ببساطة إلى مجموعات أنشأتها API.

توجد خدمات غير رسمية تستعمل جلسة WhatsApp Web لإرسال رسائل إلى مجموعات، لكنها قد تعرّض الحساب للفصل أو التقييد وتحتاج إدارة جلسة وتأمينها؛ لا نعتمدها تلقائيًا ولا نربط الرقم الأساسي من خلالها.

**بدائل معتمدة تحتاج موافقة المكتب:**
- إرسال التنبيه منفصلًا إلى أرقام الموظفين عبر WhatsApp Cloud API، وفق موافقتهم وقوالب Meta المعتمدة ومصاريف الإرسال المحتملة.
- إرسال تنبيه إلى مجموعة Telegram خاصة بالموظفين عبر Telegram Bot API.
- عرض قائمة التنبيهات الخاصة في لوحة استوديو أبو الفيصل بعد إنشاء تسجيل دخول آمن للموظفين.

## ما الذي نفذه الكود؟

- \`worker.js\`: استقبال Webhooks موقعة والتحقق من Phone Number ID للرقم الحالي.
- \`monitor.js\`: بدء المهلة، إيقاف المهلة عند صدور رد بشري، وعدم تكرار التنبيهات.
- \`monitor-schema.sql\`: جداول D1 الخاصة التي لا تحفظ نص رسائل العملاء.
- \`wrangler.example.toml\`: وضع \`MONITOR_ONLY = "true"\` وجدولة الفحص كل دقيقة.
- \`GET /api/monitor-alerts\`: عرض آخر التنبيهات عبر مفتاح خاص (لا تعرض المفتاح ضمن JavaScript عام).

**غير منفذ/مفعّل:** إرسال الرسالة إلى جروب واتساب، استضافة Worker، ربط Meta رسميًا، ربط شاشة داخل استوديو أبو الفيصل، وإشعارات حقيقية للموظفين.

## إجراءات الاختبار قبل الربط

- تأكيد دعم Coexistence للرقم الحالي ولأجهزة الموظفين، لأن الأجهزة المرافقة قد تُفصل عند الإعداد وتحتاج إعادة الربط. بعض أجهزة Windows غير مدعومة.
- إنشاء استضافة Cloudflare Worker وقاعدة D1 خاصة، تطبيق \`schema.sql\` و\`monitor-schema.sql\` وإضافة بيانات Meta كأسرار لا في GitHub.
- الاشتراك في حقلي \`messages\` و\`smb_message_echoes\`.
- تجربة رسالة واردة لا رد عليها: تنبيه واحد بعد مدة لا تقل عن أربع دقائق (cron كل دقيقة).
- تجربة رد الموظف قبل المهلة: صفر تنبيهات.
- تجربة تكرار رسالة العميل أو تكرار تسليم webhook: تنبيه واحد فقط.
- تجربة رد الموظف من كل نوع جهاز مستخدم بالفعل في المكتب. لا يمكن ضمان معرفة الردود التي لا تصل إلى webhook.
- ضمان ألا ترسل أي رسالة إلى العميل.

## التشغيل

لم يتم تشغيله أو توصيله بواتساب في هذه المرحلة. يجب أن يختار المكتب **وجهة إرسال مدعومة** للإنذارات قبل إكمال التفعيل. حتى ذلك الحين تُحفظ التنبيهات في قاعدة خاصة ولا يتم إرسالها.
